房间光影质量路线对比（对照 room-interior-v1）

目标图 room-interior-v1.png 的气质差，主要在间接光（墙角漏光、暗部层次）与光泽反射（地板镜面感、金框高光）。 现管线是瘦 GLB + MeshStandard + 实时几盏灯，浏览器实时渲染很难直接追上 Cycles / 离线那张图。 下面三条路线对照投入与能闭上的缺口；B 为已选路径。

已锁约束（本阶段）

  • 仍 Vite + React + R3F；不换 Unity / Unreal 进实时；不引入 Houdini 进实时链路
  • 资产规则不变：瘦 GLB（不带贴图）+ 贴图 JPG；门牌不烤进贴图
  • 八门共用一室内壳；走廊与房间各一套 Canvas
  • 不做画芯/黑板编辑器、存档、物理（明确延期项）

A. Three.js 实时增强 可选增强

仍纯实时：IBL / PMREM、材质光泽、ACES、软阴影 — 拉近光泽，暗部电影感有限。

优点

  • 改动集中在前端与一份 HDR，不动烘焙管线
  • 地板 / 金框立刻有真反射，和目标图的「亮」更接近
  • 与现有入场闪灯、拉线台灯兼容最好

缺点

  • 墙角、天花间接光仍靠实时灯硬撑，暗部层次难追 PNG
  • 多灯 + 软阴影成本上升，移动端更吃紧
  • 再抠 roughness 也补不出 Cycles 那种漏光
投入：约 0.5–2 天（HDR + 材质 + 色调映射对照）

对照目标图能闭上：金属/地板光泽、高光形状。仍缺口：间接光、软边漏光、整体电影暗部。

B. Blender 烘焙进网页 推荐 / 已选

Cycles 烘 lightmap / AO → 第二套 UV → 前端 lightMap/aoMap。网页里性价比最高的「高质量」。

优点

  • 墙角漏光、地板受光、暗部层次最接近目标 PNG
  • 仍留在现有 Vite+R3F；不换引擎、不破瘦 GLB+JPG 规则
  • 八门共一壳：烘一次，全门复用
  • 与文档「预烘 lightmap」以后档一致，房间静帧最适合先做

缺点

  • 要做 UV2、烘焙验收、防 UV 重叠
  • 进场闪灯与烘焙光需约定（稳定态烘 + 实时只调 emissive）
  • 多几张 JPG，包体略增；分辨率要控
投入：约 3–7 天分批（Bake0 大面试点 → 家具 → 调参验收）

对照目标图能闭上：间接光、暗部层次、大面受光气质。光泽仍可叠 A 的 IBL 作加分项。反射镜面感不如纯实时 IBL 灵活，但整体气质最接近。

C. Unity 6 / Unreal 独立客户端 文档以后

实时 GI、探照灯、体积雾 — 产品升级才换栈；本阶段明确不做。

优点

  • 实时 GI / 体积雾 / 探照灯上限最高
  • 工具链成熟，美术调光反馈快

缺点

  • 整站栈重写；与现 Vite+R3F、八门共壳方案断裂
  • 分发、体积、维护成本远超个人站需求
  • 文档已写明本阶段不做
投入：周～月级产品决策，非本阶段工作项

对照目标图：上限可齐甚至超越，但不解决「在现网页里追气质」的问题。
