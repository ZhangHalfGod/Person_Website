# Profile 主页三方案对比

需求原文见 [视觉与交互需求.md](视觉与交互需求.md)。请用浏览器打开 [index.html](index.html) 看带图的对照页。

参考实现：[MechAssist-Fusion](D:/trae_git/MechAssist-Fusion)  
- 前端：Vite + React SPA（`extern-api`）  
- UI：Tailwind；mcp-gaode 为 Dark Mode First  
- 后端：Express + better-sqlite3 + JWT  
- 本地：`concurrently` 同时起 Vite 与 Express  

## 对照表

| | 方案 A CSS 3D | 方案 B Three.js | 方案 C 分层 2.5D |
| --- | --- | --- | --- |
| 初始页图 | [scheme-a-css3d-profile.png](scheme-a-css3d-profile.png) | [scheme-b-threejs-profile.png](scheme-b-threejs-profile.png) | [scheme-c-25d-profile.png](scheme-c-25d-profile.png) |
| 透视近大远小 | CSS 3D 平面，够用 | 几何真实 | 构图画出来，拉近时模拟 |
| 暖灯只照半截墙 | 渐变 / 阴影模拟 | 点光源物理衰减，最像需求 | 画在分层图上 |
| 点击中轴前进 | `translateZ` 一档 | 相机沿 Z lerp | GSAP 缩放切层 |
| 前端 | Vite React Tailwind | Vite React + R3F / Three.js | Vite React + GSAP |
| 后端 | Express + SQLite（可二期） | 同左 | 一期 JSON，二期再 Express |
| 与 MechAssist 相似度 | 最高 | 高（多一层 3D） | 中（可先静态） |
| 第一期工作量 | 中 | 高 | 低 |
| 以后做「走进房间」 | 要跳转 2D 页或再升级 3D | 最顺 | 切页最自然 |

## 需要你拍板的事项

1. **选哪套方案：A / B / C**（可先 A 验证交互，灯光不够再把走廊换成 B，房间 API 保持不变）。
2. **页面英文名**：默认 `Profile`，或 `Personal Profile` / `Bio`。
3. **第一期后端**：只要静态 JSON，还是一开始就 Express + SQLite（对齐 MechAssist）。
4. **点门**：第一期只高亮，还是直接进 `door_Page`。
5. **第一期做几对门**：建议 4 对（门 0～7），够演示前进。
6. **后退**：要不要同时做（建议要）。

## 文档作者建议

- 视觉（灯、半截墙、灭点）优先 → **方案 B**  
- 工程同源、尽快可点 → **方案 A**  
- 先当概念站、内容未定 → **方案 C**
