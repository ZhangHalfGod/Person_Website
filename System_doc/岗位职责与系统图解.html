3. 当前系统坐标系图解

模块之间不共用一套世界坐标。 走廊 Canvas 卸载后，房间是全新原点。两边交互只传 doorId（字符串 0–7），不传 x/y/z。 单位均为米。Y 向上。相机眼高 CAM_Y = 1.56。

3.1 世界轴 vs 画面左右（朝 +Z 看时）

文档约定「X 左负右正」是世界系。Three.js 相机看向 +Z 时，相机右轴是世界 -X，所以： 画面左边 = 世界 +X，画面右边 = 世界 −X。 走廊 side: "left" 的门在世界 −X（文档的左墙）；房间为了对上「画面左画、画面右黑板」，画在世界 +X，黑板在世界 −X。

3.2 走廊俯视（XZ）与停驻点

图 2 · 走廊俯视。公式：getStopZ(i) = i × 7，getDoorZ(i) = stopZ + 3.25。

3.3 全流程相机坐标变化（走廊同一 Canvas）

阶段 position lookAt 其它
LOOK_FORWARD stop i (0, 1.56, 7i) (0, 1.56, 7i + 20) 只改 z，不平移 x
WALKING_FORWARD / BACK z 从 7i 插值到邻站，约 1s 始终 (0, 1.56, 当前z + 20) 结束后 stopIndex ± 1
TURNING_TO_DOOR 左 / 右 停在 (0, 1.56, 7i) 插值到 (±2.05, 1.22, doorZ) 约 0.75s；左 −X，右 +X
DOOR_OPENING 同上，仍看向该门 保持门的 lookAt 门绕墙铰链 rotateY ≈1.55s，然后 卸载本坐标系

3.4 房间俯视（另一套原点 · 另一 Canvas）

图 3 · 房间俯视。入场 0–2.5s 只转动门；0–10s 只改灯光强度。相机位姿固定。

3.5 模块之间的「坐标交互」

从 到 传什么 不传什么
走廊门点击 路由 navigate(/room/${doorId}) 走廊的 x/y/z、yaw、stopIndex 都不写入 URL
zustand 走廊 store 再进走廊 stopIndex 仍在内存里（Back 后还在第几对门） 房间相机位姿。走廊会 resetLook() 朝前
rooms.json 两模块只读 id, stopIndex, side, label 三维坐标。坐标写在各自 cameraStops.js / roomLayout.js
房间 Back / 无 payload 不把房间桌椅坐标带回走廊

以后若做「无缝走进同一场景」，才需要把房间原点接到走廊 getDoorZ(stopIndex) 上。第一期明确不做，以免和物理扩展搅在一起。

5. 现在需要增加的东西

按「谁来交、交什么」排列。不要把后端/物理塞进这一批。

立刻（为了对上参考图的细腻）

  • 3D 美术 走廊：地板 / 墙裙 / 门板 / 黄铜 的 albedo + roughness + normal（2K 起）。放到 Code/public/textures/Main/。
  • 3D 美术 房间：金框（最好带雕花法线或 GLB）、画灯、桌凳、天花格子。放到 Code/public/textures/door/ 与 public/models/。
  • TA + 前端 资产命名规范（米、Y-up、铰链在模型哪一侧）和一份 licenses.txt。
  • 前端 有贴图后：换 MeshStandardMaterial 贴图、轻 bloom、收地板反光。布局与状态机不动。

可选增强（仍第一期气质，不必等后端）

  • 房间入场门更明确地出现在画面左前景（参考 room-interior-v1.png）。
  • 走廊墙裙做出矩形线脚（模型或法线），吊灯换成有灯罩的 GLB。
  • HUD 字体更接近原型（小字、低存在感）。不要加菱形准星或地面圆圈。

明确以后再加（现在不要做）

  • 后端 画布内容、黑板字、桌子状态的读写 API。
  • 前端交互 点画 / 点黑板 / 点桌子进入编辑（extensions/interact/）。
  • 物理 Rapier / Cannon 重力碰撞。
  • 走廊与房间合成同一个 Canvas 的无缝步行。

你作为负责人现在只要准备

  • 第一批贴图或购买/下载的 CC0 包路径（哪怕只有地板+墙+门）。
  • 一句话范围：「只升走廊」还是「走廊+房间一起升材质」。
  • 不必先招后端；不必再出带准星的原型图。
