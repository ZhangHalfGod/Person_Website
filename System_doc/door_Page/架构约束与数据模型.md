# 架构约束与数据模型 — 房间页

## 路由

| 路径 | 页 |
| --- | --- |
| `/` | 走廊 Profile |
| `/room/:doorId` | 本页；`doorId` ∈ `0`…`7` |
| 其它 | 回 `/` |

数据仍读 `Code/Module/Main/data/rooms.json`（`@main/data/rooms.json`），不新增 API。

## 房间坐标（建议）

- 相机进门后偏房间中心，看向桌子。
- 桌子在相机前方偏中。
- 画在 **-X 墙**（画面左边）。
- 黑板在 **+X 墙**（画面右边）。
- 入场门在相机 **后方或侧后**（开门是「身后/身侧的门打开，灯光亮起」）；若更好拍，也可让门在视野边缘打开。不要挡住桌画黑板。

## 道具数据（第一期写死在场景，仅预留 id）

```text
table      实心木桌
stool-1..n 实心木凳
painting   白色画芯 + 精美画框
blackboard 白色板面 + 框，无字
```

以后交互用这些 id 挂钩，第一期不要绑 `onClick` 业务。

## 与走廊的边界

- 房间 **新 Canvas**，不把走廊场景卸载失败留在内存即可（路由切换卸载走廊）。
- 走廊开门动画结束才 `navigate`；房间自己再播一次门打开（入场），两段可以都有。
